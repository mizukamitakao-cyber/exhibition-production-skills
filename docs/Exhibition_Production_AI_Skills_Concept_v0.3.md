# 企画展示制作AI Skills 基本構想 v0.3

策定日：2026年11月17日  
文書区分：基本構想・要件定義  
ステータス：設計案

## 1. 基本構想の概要

### 1.1 目的

本構想は、博物館・資料館等における企画展示の制作業務を、AI Skillsによって体系的に支援するシステムの開発方針を定めるものである。

本システムは、企画アイディアの創出から資料調査、企画書作成、展示構成、パネル・キャプション原稿、デザイン案、品質レビューまでを一貫して支援する。既存展示の改訂にも対応し、展示内容の検証、改訂方針の策定、原稿修正、変更履歴の管理を可能にする。

**AIが制作を支援し、展示の専門的・倫理的判断と最終承認は人間が担う。**

### 1.2 開発の基本方針

| 項目 | 方針 |
|---|---|
| 対象施設 | 博物館、資料館、文化施設等 |
| 開発環境 | Claude Codeで先行開発 |
| 対応環境 | Claude Code・Codex |
| システム構成 | 共通Skills＋専門分野別設定＋館別プロファイル |
| ナレッジ管理 | ローカルファイルを基本とする |
| 進行方式 | AIとの対話・段階承認 |
| 対応業務 | 新規展示制作・既存展示改訂・個別作業 |
| 品質管理 | AdvocateとReviewerを分離 |
| 初期検証 | 架空データを中心に検証し、許諾済み実資料へ展開 |
| 将来展開 | 他館への導入・カスタマイズ・保守サービス |

### 1.3 目指す成果

- 展示制作に必要な調査・整理・執筆の負担軽減
- 企画アイディアの多様化と質の向上
- 展示内容の正確性、根拠の追跡可能性の向上
- 展示制作ノウハウの蓄積・再利用
- 館ごとの専門性や制作方針に対応したAI活用
- 継続的に改良・提供できる製品基盤の確立

## 2. システムの基本アーキテクチャ

共通コア、Claude Code／Codex用の環境別アダプター、Deployment Setup／Museum Onboarding、館別プロファイル・ナレッジ・展示案件の四層を基本とする。

**共通コアは館固有の情報を持たない。** 各館の使命、専門領域、執筆規程、展示方針、資料情報は外部設定として管理する。

Claude CodeとCodexの違いは環境別アダプターで吸収し、共通のデータ形式と処理仕様を維持する。ただし両環境で完全に同じ出力が得られることまでは保証しない。互換性の対象はデータ構造、主要機能、承認状態、品質基準とする。

## 3. 対応する業務範囲

### 3.1 新規展示制作

1. **アイディア創出** — テーマの発散、比較、選定
2. **資料調査** — 史料・研究・収蔵資料等の確認
3. **企画立案** — 目的、対象、コンセプト、実施条件の整理
4. **展示構成** — 章立て、ストーリー、展示資料の配置案
5. **原稿制作** — パネル、キャプション、導入文
6. **デザイン案** — レイアウト、配色、情報設計
7. **レビュー・承認** — 批判的検討、品質確認、修正

### 3.2 既存展示の改訂

| 工程 | 主な処理 |
|---|---|
| 原本取り込み | 既存企画書、構成表、原稿、図版等を読み込む |
| 現状診断 | 史実、構成、表現、来館者視点、資料利用を評価 |
| 改訂方針 | 維持・修正・追加・削除を判定 |
| 改訂作業 | 承認された範囲で原稿や構成を変更 |
| 差分管理 | 変更前後、理由、根拠を記録 |
| 最終確認 | 変更箇所と影響範囲をレビュー |

原本は上書きせず、改訂版を別途保存する。

### 3.3 個別作業モード

企画書の一部分だけの作成、キャプション校正、展示構成レビューなど、個別Skillの利用にも対応する。全工程を順番に実行する必要はない。

## 4. Skillsの構成と役割

| Skill | 主な役割 |
|---|---|
| Deployment Setup | 実行環境の選定・設定・動作確認 |
| Museum Onboarding | 館の特性をヒアリングし、館別プロファイルを作成 |
| Exhibition Director | 工程統括、対話、作業指示、承認管理 |
| Idea Generator | 企画テーマの創出、比較、深掘り |
| Researcher | 調査、出典管理、未確認事項の整理 |
| Planner | 企画書、実施計画、条件整理 |
| Story Designer | 展示構成、章立て、ストーリー設計 |
| Exhibition Writer | パネル・キャプション等の執筆・改訂 |
| Visual Designer | デザインコンセプト、レイアウト試作 |
| Advocate | 批判的検討、見落としの指摘、代替案提示 |
| Reviewer | 事実、出典、表記、権利、要件適合性の検証 |

これは11の**論理機能**であり、すべてを独立エージェントとして実装することを意味しない。共通処理はスクリプトやライブラリとして実装する。

Advocateは「そもそもこの展示でよいのか」を問い、Reviewerは「この成果物が基準を満たしているか」を確認する。両者の指摘は記録し、採否は担当者が決定する。

## 5. 導入・初期設定の基本構想

### 5.1 Deployment Setup

| 要件ID | 機能 | 内容 |
|---|---|---|
| DEP-01 | 環境診断 | OS、PC性能、利用権限、ネットワーク条件を確認 |
| DEP-02 | AI環境選定 | Claude Code・Codexの適合性を比較 |
| DEP-03 | 実行環境設定 | 必要なツール、Skills、依存関係を設定 |
| DEP-04 | 保存先設定 | データ保存先とアクセス権限を確認 |
| DEP-05 | セキュリティ確認 | AIへの入力制限、資料の取扱い方針を確認 |
| DEP-06 | 動作検証 | 読み取り、書き込み、承認、再開を検証 |
| DEP-07 | 導入記録 | 環境構成、製品版、設定内容を記録 |

選定では機能だけでなく、料金、組織のセキュリティ方針、操作習熟度、保守性を考慮する。

### 5.2 Museum Onboarding

ヒアリング項目は、基本情報（館名・種類・設置目的・専門分野）、来館者・教育方針、展示制作規程、資料・調査基準、品質・倫理、運用・承認とする。

原則1回1〜3問とし、既存資料から確認できる情報は重複して質問しない。不明な設定は未設定として扱い、AIの提案を正式方針として自動登録しない。

### 5.3 館別プロファイルの構成

| 階層 | 内容 |
|---|---|
| 共通設定 | 全施設で共通する動作・安全基準 |
| 専門分野別設定 | 歴史、美術、自然史、科学等の専門ルール |
| 館別設定 | 館の使命、制作規程、資料環境 |
| 案件別設定 | 個別展示の目的、対象者、制約条件 |

下位設定を原則優先するが、原本保護、権限管理、出典捏造禁止などの共通安全基準は上書きできない。

### 5.4 プロファイルの主要データ項目

| 分類 | 主要項目 |
|---|---|
| 識別情報 | 館ID、プロファイル版、承認状態 |
| 館の基本情報 | 館名、種類、使命、専門分野 |
| 来館者 | 対象層、利用言語、アクセシビリティ |
| 展示方針 | 展示目的、教育方針、重点テーマ |
| 調査 | 優先資料、出典方式、検証基準 |
| 執筆 | 文体、文字数、用語集、表記規程 |
| デザイン | デザインガイド、パネル仕様 |
| 品質管理 | Advocate・Reviewerの評価項目 |
| 運用 | 承認方式、担当役割、成果物様式 |
| 情報管理 | データ区分、入力制限、許可済み保存先 |

保存形式はYAML、構造検証はJSON Schemaを基本とする。各設定値の出典・確認状態は別途管理し、`confirmed`、`documented`、`proposed`、`unset`、`conflict`を区別する。

### 5.5 設定の承認と更新

作成中、確認待ち、承認済み、改訂中の状態を持つ。承認済みプロファイルの更新は旧版を保持して新版を作成する。案件は利用したプロファイル版を記録し、更新を無条件に反映しない。

## 7. 展示制作ワークフロー

| 段階 | 主な成果物 | 承認ポイント |
|---|---|---|
| 企画検討 | アイディア一覧・比較表 | 企画候補の選択 |
| 調査 | 調査メモ・出典台帳 | 重要な調査課題の確認 |
| 企画立案 | 企画書 | 企画方針の承認 |
| 展示構成 | 章立て・構成表 | 構成の承認 |
| 原稿制作 | パネル・キャプション | 原稿の承認 |
| デザイン | レイアウト・試作 | デザイン方針の承認 |
| 最終確認 | レビュー結果・成果物一式 | 最終承認 |

AdvocateとReviewerは重要な承認ポイントの前に介入する。AIは承認された範囲で下位作業を連続実行できるが、企画方針の確定、承認済み原稿の変更、原資料の変更・削除、外部送信、公開・印刷・納品用の最終確定は明示承認を必要とする。承認済み内容への影響があれば再レビューする。

## 8. ナレッジ・データ管理

| データ区分 | 主な内容 |
|---|---|
| 共通ナレッジ | 展示制作手法、標準テンプレート、品質基準 |
| 専門ナレッジ | 分野別の調査・解説・レビュー基準 |
| 館別ナレッジ | 館の方針、規程、過去展示、資料情報 |
| 案件データ | 企画、調査、構成、原稿、レビュー、承認 |
| 出典台帳 | 資料ID、所在、引用箇所、確認状況 |
| 企画アイディア | 採用・保留・不採用を含む候補 |
| システム記録 | 設定変更、実行履歴、障害、製品版 |

初期の論理ディレクトリ案：

```text
exhibition-production-skills/
├── core/
├── adapters/
│   ├── claude-code/
│   └── codex/
├── schemas/
├── templates/
├── scripts/
├── tests/
└── docs/

exhibition-production-data/
└── museums/
    └── museum-001/
        ├── profile/
        ├── knowledge/
        ├── source-materials/
        ├── idea-bank/
        └── projects/
```

実際のSkill検出規則に合わせて調整する。製品更新で館別設定・案件データを上書きしない。

重要な事実は根拠資料IDに紐付け、資料名、ページ・箇所、所蔵先、参照日、検証状況を保存する。**確認済み事実、証言、研究上の解釈、AI推論を区別**し、出典不明の記述を未確認として扱う。架空の出典や引用は作成しない。

## 9. デザイン制作の基本方針

| 段階 | 支援内容 |
|---|---|
| デザイン方針 | 雰囲気、配色、書体、視覚的統一 |
| 情報設計 | 文字・写真・図版の優先順位と配置 |
| レイアウト試作 | パネル、キャプション、年表等のモックアップ |
| 制作データ | 編集可能なHTML/SVG等の出力 |
| 品質確認 | 文字量、可読性、画像解像度、寸法等の確認 |

AI生成画像と編集・印刷可能な制作データを区別する。初期開発はHTML/CSS等の編集可能な試作を中心とし、印刷・施工データの自動生成は後続段階で検討する。歴史写真や文化資料の不適切な加工、誤解を招く図版、視覚表現の偏り、アクセシビリティを確認する。

## 10. 非機能要件

| 区分 | 要件 |
|---|---|
| 正確性 | 根拠のない情報を確定情報として扱わない |
| 安全性 | 原本保護、権限管理、外部AIへの入力制御 |
| 再現性 | 使用した設定・資料・成果物の版を追跡できる |
| 継続性 | セッション終了後も作業を再開できる |
| 可搬性 | Claude Code・Codex間で主要データを共有できる |
| 拡張性 | 新しい専門分野やSkillsを追加できる |
| 保守性 | 共通製品と館別設定を独立して更新できる |
| 操作性 | 自然言語による対話を基本とする |
| 監査性 | 変更・承認・差し戻しの履歴を確認できる |
| 性能 | 不要な再調査・再生成を避け、AI利用量を抑える |

ローカル保存とAIモデルへの非送信は同義ではない。館ごとにAI入力可否、外部サービス条件、保存・削除方針を設定する。著作権、肖像権、個人情報、利用許諾は確認支援の対象だが、最終的な適法性は保証しない。

原本と作業データを分離し、重要な更新履歴、書き込み障害対応、バックアップ・復旧、未承認領域の書き込み防止、競合検出を実装する。

## 11. 製品化・導入サービスの構想

### 11.1 提供形態

1. **基本パッケージ** — 共通Skills、標準テンプレート、初期設定ガイド、操作マニュアル
2. **導入支援サービス** — 環境診断、Museum Onboarding、ナレッジ整備、カスタマイズ、試験運用、職員研修
3. **保守・機能拡張サービス** — 更新、AI環境仕様変更対応、独自機能追加、運用改善

### 11.2 標準導入プロセス

| 段階 | 作業 | 成果物 |
|---|---|---|
| 1. 導入診断 | 業務・IT環境・AI利用方針を確認 | 導入診断書 |
| 2. 環境選定 | Claude Code・Codexを比較 | 環境構成案 |
| 3. 初期設定 | Museum Onboardingを実施 | 館別プロファイル |
| 4. ナレッジ整備 | 資料・制作規程・過去展示を整理 | 館別ナレッジ |
| 5. 試験運用 | 実際の業務に近い条件で検証 | 検証報告書 |
| 6. 納品・研修 | 設定済みSkillsと操作方法を提供 | 導入パッケージ |
| 7. 保守 | 更新・改善・問い合わせ対応 | 保守記録 |

製品本体、導入支援、AIサービスの料金を区別する。開発者成果物、顧客固有情報、共同制作成果物、第三者権利対象を分離し、契約で権利・利用条件を定める。勤務先の非公開情報や権利帰属資料は許諾なく利用しない。

## 12. 開発ロードマップ

| Phase | 開発内容 | 到達目標 |
|---|---|---|
| 1 | 共通基盤・スキーマ設計 | 設定と案件データを安全に管理できる設計を確定 |
| 2 | Deployment Setup・Museum Onboarding | 導入環境と館別設定を構築できる |
| 3 | Exhibition Director・Idea Generator | 対話型の企画検討を実行できる |
| 4 | Researcher・Planner・Story Designer | 出典付き企画書・展示構成を作成できる |
| 5 | Exhibition Writer・Advocate・Reviewer | 原稿制作・改訂・品質検証ができる |
| 6 | Visual Designer・成果物出力 | 編集可能なレイアウト試作ができる |
| 7 | Codex対応・製品化検証 | 複数環境で導入・更新・運用できる |

各Phaseは設計→レビュー→実装→受入試験を基本とする。初期は架空データで検証し、実資料利用には権利・許諾確認を要する。

### 12.2 MVPの範囲

1. Museum Onboardingによる館別設定
2. Exhibition Directorによる対話・段階承認
3. Idea Generatorによる企画創出
4. Researcherによる根拠管理
5. Planner・Story Designerによる企画書・構成作成
6. Writerによる原稿作成・改訂
7. Advocate・Reviewerによる検証

Deployment Setupは手順書・検証スクリプト中心とし、完全自動インストールは必須としない。Visual Designer本格実装、外部DB連携、自動配布・更新は後続開発とする。

## 13. 検証・受入基準

| 試験 | 合格条件 |
|---|---|
| 館別設定 | 異なる専門分野の館を設定できる |
| 新規制作 | テーマ検討から企画書・原稿まで作成できる |
| 既存改訂 | 原本を保持し、変更箇所と理由を追跡できる |
| 出典管理 | 重要な事実から根拠資料を参照できる |
| Advocate | 論点・根拠・改善案を提示できる |
| Reviewer | 要件違反や未確認事項を指摘できる |
| 承認 | 未承認成果物を正式版として扱わない |
| 再開 | セッション終了後も状態を復元できる |
| データ保護 | 原本・承認済みデータを誤って上書きしない |
| 環境互換 | 共通データを別のAI環境で読み込める |

意図的な誤情報、出典不明、矛盾、未承認変更要求を含むテストを行い、実務上の有用性は担当者が評価する。

## 14. 想定リスクと対応

| リスク | 対応方針 |
|---|---|
| AIによる誤情報 | 出典管理・未確認事項明示・人間の検証 |
| 展示内容の画一化 | 館別設定・Advocate・複数案比較 |
| 専門性の不足 | 分野別ルール・専門資料・人間の監修 |
| 機能の過剰開発 | MVP範囲固定・段階的拡張 |
| AI環境への依存 | 共通コアと環境別アダプターの分離 |
| 顧客データの混在 | 館ごとの保存領域と権限分離 |
| 製品更新による設定破損 | スキーマ版管理・移行・バックアップ |
| AI利用コストの増大 | 調査結果再利用・工程単位実行 |
| 権利・契約上の問題 | 開発資料の出所管理・利用条件明確化 |
| 継続保守の負担 | 標準構成・自動テスト・変更履歴 |

## 16. 基本構想v0.3の結論

1. 施設に依存しない共通製品として構築する。
2. Museum Onboardingで各館の専門性と運用方針を反映する。
3. Claude Codeで先行開発し、Codexにも対応可能な構造を維持する。
4. AdvocateとReviewerを組み込み、展示の質と正確性を両面から検証する。
5. 製品本体と顧客固有データを分離し、将来の導入・販売・保守に対応する。

最初の開発対象は**Deployment Setup・Museum Onboarding・共通データ基盤**とする。次工程は「Phase 1 詳細設計・Claude Code開発指示書」に従い、設計・環境調査を先行させ、承認後に実装する。
